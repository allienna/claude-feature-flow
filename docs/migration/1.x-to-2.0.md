# Migrating from 1.x to 2.0

2.0.0 is a major release because several command contracts changed. Existing projects keep working; you opt into new behaviour feature by feature.

## What changed

| Area | 1.x | 2.0 | Action |
|---|---|---|---|
| `/build` | Inline loop in one context | Orchestrator: parallel waves, independent review, convergence | Install the agents (below); learn the flags |
| Agents | none | `implementer`, `spec-reviewer`, `quality-reviewer`, `qa-verifier` | Plugin users: automatic. `install.sh` users: re-run it |
| `tasks.md` | `Do` + `Test` per task | adds `Depends-on`, `Files`, `Covers`, `[P]`, `## Execution Waves` | New features get it from `/tasks`. Old files run sequentially |
| Acceptance criteria | free text | Given/When/Then or EARS, `[NEEDS CLARIFICATION]` markers | `/plan` refuses untestable criteria; run `/clarify` |
| `/plan` | ran with open questions | stops while markers remain | `/clarify` |
| `/review` | one agent reviews its own work | two independent read-only agents, merged mechanically | New `review.md` layout (evidence, traceability, convergence history) |
| `/qa` | inline | delegated to `qa-verifier` | none |
| `/specify` | `git checkout -b` in place | git worktree per feature | Commit foundations to `main` first |
| `specs/roadmap.md` | statuses updated by commands | statuses derived; never edited by feature commands | Use `/status` |
| New commands | | `/clarify`, `/analyze` | optional |

## Upgrade steps

1. **Update the plugin** (`/plugin marketplace update`) or pull your clone; for `install.sh` installs re-run `./install.sh` (it now also links `agents/`).
2. **Set `worktree.baseRef: "head"`** in your Claude Code settings if you want parallel worker isolation (otherwise use `--isolate=none`).
3. **Add `## Worktree Setup`** to `CLAUDE.md` if your project needs a dependency install in a fresh checkout.
4. **Add `.claude/worktrees/` to `.gitignore`.**
5. **Commit your foundations** (`PRD.md`, `DESIGN.md`, `specs/constitution.md`, `specs/roadmap.md`, `CLAUDE.md`) to `main`.

## Features already in progress

- A track created with 1.x on a regular branch keeps working: `/implement`, `/build`, `/review`, `/ship`, `/merge` all operate on it. `/build` requires you to be on the spec's branch and runs sequentially if `tasks.md` is in the old format.
- To get parallel waves on an existing feature, re-run `/tasks <feature>` (it asks before overwriting; completed tasks are lost if you overwrite, so do it before starting the build), or add `Depends-on`/`Files`/`Covers` to the tasks by hand and re-create the waves table.
- `/merge` of an old-style branch works as before; if no worktree exists it simply skips the worktree cleanup.

## Behaviour differences to expect

- `/build` can launch several agents at once and makes **checkpoint commits** (`chore(build): wave N baseline`) on your feature branch in worktree mode; they disappear in the squash merge.
- `qa-report.md` is still written at the repository root.
- Review verdicts are stricter: any `major` issue or failing criterion is "Needs work".

## Pinning 1.0.0

If you need the previous behaviour, pin the `v1.0.0` tag (`git checkout v1.0.0` in a local clone, or install from that ref).
